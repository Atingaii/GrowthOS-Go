## 本节 API 变化

本节没有新增、修改或删除 HTTP、RPC、事件或 MCP 契约。它只确定第 11～72 节优先使用一个 Go 产品进程，并通过模块端口隔离领域职责。

| 类型 | 当前状态 | 说明 |
| --- | --- | --- |
| HTTP API | 无新增 | `GET /health` 在第 11 节实现 |
| RPC | 未引入 | gRPC 与 Protobuf 在第 75 节按拆分证据引入 |
| 领域事件 | 未实现 | 具体事件随业务用例和可靠消息章节建立 |
| MCP Tool | 未引入 | 第 81 节起实现 Gateway 契约 |

## 后续契约约束

- 进程内模块调用也必须有明确输入、输出和错误语义；
- 模块不得把数据库模型作为跨模块公共契约；
- 未来把进程内端口替换为 RPC 时，应保持业务语义并单独记录兼容策略；
- 只有第 73 节后的拆分证据成立，才新增服务间网络契约。

## 遗留问题

- 第 11 节需要定义首个健康接口和进程关闭语义；
- 第 12 节需要定义统一响应、错误码和日志关联字段。
