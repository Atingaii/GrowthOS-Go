## 后续 API 设计输入

后续真实契约需要能够关联：

- 业务对象 ID、事件类型与版本；
- `trace_id`、业务请求号和幂等键；
- 用户、运营、系统或 AI 任务等行为主体；
- 成功、业务拒绝、技术失败、超时、部分成功和结果未知；
- 事件采集失败时的重试、去重和补偿语义。

这些字段只是设计检查项，不在本节锁定路径、HTTP 方法、JSON 结构或消息协议。

## 遗留问题

- 第 6 节先确认限界上下文和跨上下文事件，再决定哪些事件需要成为同步 API 的响应或异步消息；
- 第 7 节已在[非功能需求基线 v1](../../product/non-functional-requirements-v1.md)中把事件可追踪性、延迟、重复、丢失和恢复转成候选目标；
- 实现事件采集时必须区分分析行为事件和参与、账户、权益等核心业务事实；
- 实现 AI Tool 时不能把模型文本或页面提示作为业务成功响应。
