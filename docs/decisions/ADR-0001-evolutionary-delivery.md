# ADR-0001: Evolutionary Delivery

- **Status:** Accepted
- **Date:** 2026-08-08
- **Owners:** GrowthOS maintainers

## Context

GrowthOS 横跨营销、增长数据、AI 工具和生产运维。如果初始化时一次性定义最终表结构、微服务和基础设施，课程会隐藏真实决策过程，并把未经验证的假设固化为代码。

## Decision

采用需求驱动的演进式交付：每个阶段先实现满足当前需求的最小正确方案，再用新需求、测量结果或故障证据推动 Migration、领域模型重构和架构变化。

数据库只通过前向 Migration 演进。每次结构变化必须解释原设计为何不足、选择、查询与写入影响、并发与一致性后果以及回退/补偿方法。最终 ER 图只在第 96 节基于实际演进结果生成。

## Consequences

- 课程保留“当时合理、后来不再适用”的方案及升级证据。
- 目录、Schema 和服务拓扑不会在项目开始时稳定。
- 迁移兼容、历史解释和阶段性 QA 是实现的一部分。
- 不允许为了与预设终态一致而重写历史 Migration。
