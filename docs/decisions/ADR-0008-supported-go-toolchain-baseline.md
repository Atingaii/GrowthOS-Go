# ADR-0008：采用受支持的 Go 工具链基线

- **状态：** 已接受
- **日期：** 2026-08-29
- **负责人：** GrowthOS 维护者

## 背景

仓库最初在没有产品运行时依赖时声明 `go 1.24.0`。第 11 节开始引入 Gin 和真实 HTTP 进程，此时继续维持旧基线会产生两个问题：

1. Go 官方的[发布策略](https://go.dev/doc/devel/release#policy)规定，一个大版本只支持到两个更新的大版本出现；按[发布历史](https://go.dev/doc/devel/release)，实施日已经发布 Go 1.27，因此 Go 1.24 已离开官方支持窗口，而 Go 1.26 仍在支持窗口内。
2. 本地实际验证工具链是 Go 1.26.6，CI 又通过 `actions/setup-go` 的 `go-version-file: go.mod` 读取仓库基线。若 `go.mod` 继续写 1.24.0，本地与 CI 的最低版本事实不一致，依赖升级也可能在不同工具链下得到不同结果。

Go 1.26.6 的官方发布记录包含 `go` 命令、`crypto/tls`、`encoding/xml`、`html/template`、`net/http` 等组件的安全修复。把最低基线从已经停止支持的 1.24.0 提升到经过本机验证的 1.26.6，既纳入这些补丁，又让 CI 能从仓库文件确定同一工具链版本。

这项决策不是宣称 Go 1.26.6 永远是最新补丁。`go` 指令表达项目最低要求；同一受支持分支的更高补丁版本仍可使用，并应按官方发布历史及时评估和升级。

## 评估过的方案

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 保持 Go 1.24.0，并固定旧版 Gin | 眼前无需抬高最低工具链 | Go 1.24 已停止官方补丁支持，本地与 CI 基线继续漂移 | 不采用 |
| 只升到 Gin v1.12.0 所需的 Go 1.25 | 变更幅度较小 | 实施日 Go 1.25 也已因两个更新大版本出现而退出支持窗口 | 不采用 |
| 最低基线升到本机已安装的 Go 1.26.6 | 仍在官方支持窗口，已完成本机验证，可由 `go.mod` 驱动 CI | 开发者和 CI 需要更新工具链，后续仍需维护补丁版本 | 采用 |
| 立即要求 Go 1.27 | 使用最新大版本 | 当前本机与既有验证环境尚未建立该基线，超出本节必要范围 | 暂不采用 |

## 决策

1. 根 `go.mod` 的最低工具链改为 `go 1.26.6`；本地开发和 CI 都以该文件为版本事实源。
2. 第 11 节接受 [Gin v1.12.0 官方版本](https://github.com/gin-gonic/gin/releases/tag/v1.12.0)。其官方 [`go.mod`](https://github.com/gin-gonic/gin/blob/v1.12.0/go.mod)要求 Go 1.25.0，项目的 Go 1.26.6 基线满足该要求。
3. CI 继续使用 `actions/setup-go` 的 `go-version-file: go.mod`，避免另写一份容易漂移的 Go 版本；依赖版本继续由 `go.mod` 与 `go.sum` 共同固定。
4. Go 的[工具链选择规则](https://go.dev/doc/toolchain)仍然适用：低于最低要求的工具链必须拒绝构建或按显式的 `GOTOOLCHAIN` 策略取得满足要求的工具链，不能静默退回不受支持版本。
5. 后续 Go 补丁升级应检查官方发布历史、安全修复、依赖兼容和全仓门禁；大版本基线变化继续用 ADR 或明确的替代决策记录。

## 影响

- 开发者需要 Go 1.26.6 或满足最低要求的更新工具链；旧环境必须升级后再运行项目门禁。
- `go.mod`、本机 `go version` 与 CI 的 setup-go 输入统一，减少“本地用新工具链、CI 却按旧最低版本解释”的漂移。
- 可以采用 Gin v1.12.0 的修复和改进，不再为保留已停止支持的 Go 基线而固定 Gin v1.11.0。
- 升级不会改变 `GET /health` 的路径、响应或进程生命周期契约；相关行为仍由第 11 节自动化测试保护。
- 工具链升级不代表 MySQL、Redis、消息队列或任何业务能力已经接入。
- Go 1.26.6 是当前可复现的最低检查点，不是免维护承诺；发现新安全补丁或支持窗口变化时必须重新评估。
