# ADR-0006：采用统一 React 前端框架承载四类工作台

- **状态：** 已接受
- **日期：** 2026-08-08
- **负责人：** GrowthOS 维护者

## 背景

第 14 节需要开始建设前端，但用户端、运营后台、MCP Gateway 和 AI Operator 会在后续章节持续增加页面。如果现在只创建一个健康检查页，后续会反复重做路由、布局和视觉基础；如果提前伪造所有业务接口，又会把未来实现误写成当前事实。

本次收到一套已经完成的 GrowthOS UI 设计源码，包含 React、Vite、Tailwind、路由、布局、Mock 数据和主要业务页面。项目需要复用这套视觉设计，同时保持 Go 业务后端按需求逐步接入。

## 评估过的方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 每个章节临时新增页面和布局 | 不采用 | 视觉、路由和状态边界会重复建设 |
| 现在创建最终业务 API 和完整状态 | 不采用 | 会把尚未验证的后端能力伪装成已完成事实 |
| 复制设计源码作为统一前端框架，业务 API 使用 Mock/真实接口边界 | 采用 | 一次稳定工程骨架，后续按业务章节替换 Mock 并联调 |

## 决策

`web/` 采用单 React + TypeScript + Vite 应用，统一承载用户端、运营端、MCP Gateway 和 AI Operator。完整搭建路由、布局、组件、Mock 数据、主题和错误页面，但不宣称尚未存在的 Go API 已经实现。设计包中的 Figma Make 专属配置和元文件不进入仓库，避免运行时依赖设计工具。

## 影响

- 视觉语言以设计包为基线，后续不合适时可在同一框架内调整；
- 服务端状态未来可从 Mock 切换到 Gin HTTP API，页面不直接依赖请求细节；
- 当前前端页面属于框架和演示数据，业务完成度仍以课程章节和后端 QA 为准；
- 增加 Node.js/pnpm 前端构建验证要求；
- 用户端、运营端和 AI 工作台暂不拆成多个前端工程，直到部署或权限边界证明拆分必要。
