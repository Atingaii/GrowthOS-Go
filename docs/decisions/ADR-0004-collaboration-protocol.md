# ADR-0004：双代理协作协议

- **状态：** 已接受
- **日期：** 2026-08-12
- **负责人：** GrowthOS 维护者

## 背景

仓库同时由 Codex 与 Claude 两个 AI 代理参与开发。没有固定职责和闭环流程时，容易出现角色重叠、跳过测试或文档、验收标准不一致等问题。需要一份单一权威规则，分别被两个代理自动读取，避免各自维护一份漂移的规则。

## 评估过的方案

1. **无规则 / 仅人类惯例**：不可行，两个代理不会共享非正式惯例。
2. **分别在 AGENTS.md 与 CLAUDE.md 各自写全**：入口各自维护，规则容易漂移。
3. **单一规范正文 + 两个入口文件**（采用）：权威正文一份，`AGENTS.md`/`CLAUDE.md` 只做入口指针，任何修订只改正文。

## 决策

采用 **单一规范正文 + 入口文件** 的结构：

- 权威正文：`docs/standards/collaboration-protocol.md`。
- 入口：根级 `AGENTS.md`（Codex 读取）与 `CLAUDE.md`（Claude 读取），均只指向正文。
- 固定职责：Codex 是规划与验收负责人，不实现也不测试；Claude 是唯一实现与测试负责人。
- 完整闭环：Codex 下发任务包 → Claude 实现 → Claude 测试 → Claude 编写交付报告 → Codex 仅基于 diff/文档/测试证据验收；不通过则由 Codex 给出缺口并重新委派，直到通过或明确阻塞。
- 交付/QA 记录必须含：任务与范围、实现摘要、变更文件、测试命令、测试结果、失败与修复、未解决风险/阻塞、验收标准逐项映射。

## 影响

- 两个代理在仓库根自动读到同一份规则，职责和验收标准一致。
- Codex 不再自行改代码/跑测试，Claude 必须为每个任务留测试证据并同步文档。
- 纯文档与治理变更（如本协议）同样走文档治理流程并记 QA 证据。
- 规则如需演进，改 `collaboration-protocol.md` 一处即可；入口文件保持指针不变。
