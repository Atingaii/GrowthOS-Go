# 第一性原理设计手记

本目录保存每一节实现背后的“推导过程”：在当时已经知道的事实、约束和风险下，为什么形成当前边界，哪些方案被排除，什么新证据会迫使我们重新决策。

它不是把代码换一种说法，也不是为既有结论补一段漂亮理由。手记必须允许后来者重放决策：即使不知道最终实现，也能从相同事实走到大致相同的需求；如果前提变化，也能明确指出哪一步推导已经失效。

## 与其他章节文档的分工

| 文档类型 | 核心问题 | 应写内容 | 不应由它代替的内容 |
| --- | --- | --- | --- |
| Course | “这一节按什么顺序学会并实现？” | 章节目标、实现路径、当前行为、复盘和下一步 | 不展开所有候选方案和假设账本 |
| QA | “我们凭什么说交付成立？” | 实际环境、命令、结果、失败数、清理与剩余风险 | 不把设计意图当成验证结果 |
| Interview | “如何准确、简洁地解释和应对追问？” | 问题、回答骨架、权衡表达、易错点 | 不作为项目事实源或决策记录 |
| Design Thinking | “从哪些事实与失败模型推导出这些边界？” | 前提、推导链、候选矩阵、不变量、信任边界、风险与重决策条件 | 不写逐步操作教程，也不宣称测试已经执行 |

还有两类相邻文档需要区分：ADR 固化跨章节仍需遵守的规范性决策，Runbook 规定操作者在正常发布和故障中怎么做；设计手记可以比 ADR 更开放，保留被否决选项、未验证假设和未来分叉，但不能修改 ADR 已经接受的事实。

## 每节固定模板

以后每节的 `lessons/lesson-NN.md` 固定包含以下内容。纯产品分析章节可以按适用性缩减运行时细节，但不能跳过事实、备选方案、风险与证据边界。

1. **决策命题与时间切片**：说明此刻要决定什么、已有能力是什么、尚未发生什么。
2. **不可争辩的事实与约束**：区分代码事实、业务事实、平台约束、外部系统事实和仍待验证的假设。
3. **为什么现在做、为什么不多做**：说明决策时机与范围边界，尤其解释“没有实现”的部分。
4. **从第一性维度推导需求**：至少检查事实源、故障域、权限、发布、可逆性、可观测性和学习成本；按“事实 → 风险 → 必须建立的机制”书写。
5. **备选方案矩阵**：列出真正可行的替代方案、当前代价、采用结论和触发重评条件，禁止用稻草人方案衬托结论。
6. **不变量与信任边界**：写出任何实现都必须保持的性质，以及数据、身份、代码和操作者跨越边界时需要的验证。
7. **资源所有权、并发与时间预算**：明确谁创建、谁接管、谁关闭，哪些操作可并发，timeout 之间为何有顺序关系。
8. **失败模型与恢复语义**：覆盖部分成功、重复、乱序、旧版本、取消、依赖抖动和恢复人员可能犯的错误。
9. **安全与隐私推导**：从最小权限、传输安全、秘密生命周期和可见输出推导防线，而不是罗列安全名词。
10. **证据设计**：逐条说明测试或评审试图证伪什么，以及仍然证明不了什么；“测试绿色”本身不是论证。
11. **被刻意推迟的能力**：记录暂不实现的内容、推迟理由、风险和明确的重新决策触发器。
12. **需求未提但架构师会主动检查的点**：容量总账、发布顺序、运维恢复、供应链、成本、合规、长期兼容等。
13. **假设与风险账本**：为假设编号，写明当前证据、失效影响、监测信号和下一次复核时点。
14. **未来演进问题**：保留下一节或未来里程碑必须回答的问题，不提前伪造答案。
15. **可追溯证据**：相对链接到对应代码、测试、ADR、课程正文、API 契约、QA 和 Runbook。

## 完成标准

一份设计手记只有同时满足以下条件，才算完成：

- 叙述忠于当前代码时间切片，规划、假设和已实现事实有清楚标记；
- 至少存在一条可复核的“事实 → 风险 → 需求 → 机制 → 证据”完整链路；
- 被选方案与至少两个真实替代方案在相同评价维度下比较，并写明重评触发器；
- 明确列出不变量、信任边界、资源所有权和部分失败，不只描述成功路径；
- 对“本节没有做什么”给出范围理由，不能把未来能力倒灌为当前实现；
- 测试章节说明每类证据能证明和不能证明什么，包含至少一个反例或负向断言；
- 假设与风险有编号、有失效影响、有观察信号，不能只写“后续优化”；
- 重大长期约束与 ADR 一致，实际结果与 QA 一致，操作建议不与 Runbook 冲突；
- 所有本地相对链接有效，不包含密码、DSN、内网地址、个人数据或临时环境秘密；
- 通过 `make doc-check`；若尚未进入上层导航，必须在交付说明中明确记录索引缺口。
