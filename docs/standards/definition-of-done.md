# 完成定义

一个实现或课程章节只有同时满足适用项，才可以标记完成：

- 业务诉求、范围和非目标明确。
- 代码格式化、编译并通过相关单元/集成/接口测试。
- 数据库变化通过新 Migration 表达，并验证升级路径。
- API、事件、配置和数据契约已同步更新；前端 API 变化已登记到 `docs/api/lessons/`。
- 重大选择有 ADR，且替代关系清楚。
- QA 文档记录实际执行命令、结果、日期与剩余风险。
- 第一性原理设计手记记录事实、推导链、真实备选方案、不变量、失败模型、风险账本与重新决策触发器。
- 面试问答包含可口述答案、追问、项目证据、选型边界与来源分级；不得把面经自述伪装成已核验原题，也不得把计划写成实绩。
- 已配置个人 Obsidian Vault 时，最终执行 `make docs-sync VAULT=/absolute/path/to/growthOS`，并把命令、结果与一致性证据写入 QA；当前执行环境无法访问个人 Vault 时，QA 必须如实记录原因，不能伪造成功结果。
- 课程正文包含本节复盘和下一节遗留问题。
- `docs/course/status.csv` 与实际产物一致。
- `make verify` 在干净工作区重新执行通过。
- 提交不包含秘密、临时产物或与本节无关的实现。

早期纯分析章节不强行要求代码或数据库。其完成证据由需求覆盖、边界审查和问题清单构成。

上述设计手记与面试问答规范从第 13 节开始执行；第 1～12、14 节是规范建立前的已完成时间切片，必须逐节回填。回填完成前，`status.csv` 仍只登记原有正文与 QA 证据，不得声称两套新增材料已经全覆盖。
