# 双代理协作协议

**状态：** 已接受（见 [ADR-0004](../decisions/ADR-0004-collaboration-protocol.md)）
**更新日期：** 2026-08-12

本文件是 GrowthOS-Go 仓库中 **Codex 与 Claude 双代理协作的唯一权威规则正文**。根级 `AGENTS.md` 与 `CLAUDE.md` 只作为入口指向本文件，任何职责或流程修订都必须改这里，禁止在入口文件中单独维护一份规则副本。

## 激活边界

本协议不是始终生效的通用规则，仅在下述条件下激活：

- **激活条件**：当前会话由 CCB 管理，且 Codex 与 Claude 作为**同一 CCB 项目**的协作代理存在（项目存在 `.ccb/` 运行时且由 CCB 调度，如 `.ccb/ccb.config` 与 CCB 运行时上下文）。此时适用本协议的全部职责、任务包、交付、验收与同步门禁。
- **不激活条件**：单独运行 Codex、单独运行 Claude、非 CCB 会话、或没有 CCB 项目上下文时，本协议不激活。此时：
  - 不适用双代理职责分工、任务包、双代理验收与双代理同步门禁；
  - 不要求虚构另一代理、不要求向不存在的代理委派、不要求双代理验收；
  - 代理按宿主自身规则工作（Claude 遵循仓库 `CLAUDE.md` 与宿主约定，Codex 遵循仓库 `AGENTS.md` 与宿主约定），正常完成实现、测试与文档即可。
- **CCB 识别**：以项目存在并被 CCB 管理的上下文为准，可引用 `.ccb/ccb.config` 或 CCB 运行时作为判据；不要把普通单代理运行误判为 CCB 会话。`.ccb/` 目录仍必须排除 Git（见 [ADR-0007](../decisions/ADR-0007-obsidian-sync-gate-and-ccb-exclusion.md)），不因本协议而纳入。
- **适用对象**：本协议约束的是 CCB 双代理协作场景下的两个代理；它对普通单代理开发不构成约束，也不应被单代理误用于要求另一代理参与。

## 固定职责

| 职责 | 负责人 | 范围 |
| --- | --- | --- |
| 规划与验收 | **Codex** | 澄清目标、拆分任务、定义范围/非目标/约束/验收标准；审查 Claude 的交付记录与 diff；给出验收结论 |
| 实现与测试 | **Claude** | 所有代码与文档修改、测试执行、问题修复，并记录可复核证据 |

**Codex 不承担** 代码/文档实现，也不执行测试。**Claude 是唯一实现与测试负责人**。

## 完整闭环

每次交付必须走完下列闭环，不允许跳过测试、文档或验收环节：

```text
Codex 下发任务包
  └─> Claude 实现
  └─> Claude 测试
  └─> Claude 编写交付报告
  └─> Codex 基于 diff、文档和测试证据验收
        ├─ 通过 -> 任务关闭
        └─ 不通过 -> Codex 给出缺口 -> 重新委派 Claude 修复 -> 回到"Claude 实现"
                        （直到通过，或 Codex 判定为明确阻塞）
```

### 1. Codex 下发任务包

任务包必须明确下列字段，缺项时 Claude 应要求补齐后再开工：

- **目标**：本次交付要达成的结果
- **范围**：涉及的文件、模块或领域
- **非目标**：明确不做的事
- **约束**：技术栈、迁移、兼容性、性能或安全等边界
- **验收标准**：可逐项核查的通过条件
- **必需测试**：必须执行并给出结果的测试
- **必需文档**：必须同步更新的文档（见下方"文档同步"）

### 2. Claude 实现

- 只实现任务包范围内的事项；越界改动需先经 Codex 确认。
- 每个任务必须同步更新对应文档，不得只改代码不碰文档。

### 3. Claude 测试

- 执行任务包列出的必需测试；必要时补充针对本变更的测试。
- 测试命令、实际输出与结果必须留痕，禁止只说"已测试"而无命令与结果。

### 4. Claude 编写交付报告

每份交付/QA 记录必须包含下列字段：

| 字段 | 要求 |
| --- | --- |
| 任务与范围 | 对应的任务包与本次改动范围 |
| 实现摘要 | 做了什么、关键取舍 |
| 变更文件 | 增删改的文件清单 |
| 测试命令 | 逐条实际执行的命令 |
| 测试结果 | 每条命令的实际结果（通过/失败，附关键输出） |
| 失败与修复 | 遇到的失败、根因、修复方式与复验结果 |
| 未解决风险/阻塞 | 未覆盖项、已知风险或阻塞项 |
| 验收标准逐项映射 | 将任务包的每一条验收标准映射到证据（diff/文档/测试输出） |

### 5. Codex 验收

- Codex **仅基于 diff、文档和测试证据**做判断，不自行实现或补测。
- 通过：逐条确认验收标准均满足，给出结论并关闭任务。
- 不通过：Codex 明确指出缺口（哪条验收标准未满足、缺什么证据），重新委派 Claude 修复。循环直到通过或 Codex 判定为明确阻塞。

## 文档同步

- Claude 每个任务必须同步文档；文档变更与代码/测试在同一次交付中提交。
- 纯文档或治理类变更（如本协议）同样要更新相关索引（`CONTRIBUTING.md`、`docs/README.md`、ADR、QA 记录）。
- 文档治理遵循 [文档治理规范](documentation-governance.md) 与 [完成定义](definition-of-done.md)。

## Obsidian 最终同步门禁

项目根 `README.md` 与 `docs/` 镜像到个人 Obsidian Vault 的语义与命令见 [Obsidian 同步说明](obsidian-sync.md)。除该说明外，本协议规定如下门禁：

- **执行时点**：每个任务在所有 `README.md`/`docs/`/QA 修改完成后、提交交付报告前，必须执行最终同步。最终同步是交付前最后一步文档镜像，之后不得再修改仓库 `README.md`/`docs/`；若后续必须修改，需重新执行同步。
- **固定命令**（仓库根目录执行）：

  ```bash
  make docs-sync VAULT=/mnt/e/TencentGo/growthOS
  ```

- **Claude 证据责任**：同步命令、实际结果及对 Vault 的一致性核验（本轮新增/修改的同步范围文件在 Vault 中存在且内容与仓库源一致）必须写入交付/QA 记录。
- **Codex 验收门禁**：Codex 缺少"最终同步已执行且有证据"的记录时，不得判定验收通过。
- **无条件执行**：每个任务无论是否修改同步范围文件，都必须在交付前执行固定同步命令并记录证据，不允许跳过。同步范围文件未改动时同样执行，不留豁免。

同步范围文件指仓库根 `README.md` 与 `docs/` 下的文件；`项目README.md` 为根 README 在 Vault 中的镜像名，转换语义见 [Obsidian 同步说明](obsidian-sync.md)。

## 证据要求

- 所有"已通过/已完成"结论必须有可复核证据：命令、输出、diff 或文档链接。
- 没有证据的结论视为未完成。
