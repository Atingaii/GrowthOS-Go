# 文档治理规范

**状态：** 已接受
**更新日期：** 2026-08-29

## 原则

1. **事实就近：** 需求归产品文档，开放推导归设计手记，长期取舍归 ADR，验证归 QA，操作归 runbook，可口述复盘归面试文档。
2. **同变更更新：** 改代码、Schema、契约或运维行为时，同一提交更新对应文档。
3. **历史可解释：** 已接受 ADR 和已执行 Migration 不重写历史；通过 supersede 和新 Migration 演进。
4. **完成有证据：** 章节状态不是主观声明，必须有正文、测试或评审结果及已知风险。
5. **只写当前事实：** 规划与现状必须明确区分，不把空目录或设计草图描述为已实现能力。

## 文档所有权矩阵

| 发生变化 | 必须检查/更新 |
| --- | --- |
| 用户、业务目标或范围 | `docs/product`、课程正文 |
| 模块边界、依赖或部署拓扑 | `docs/architecture`、ADR |
| HTTP/RPC/Event/MCP 契约或前端 API 调用 | `docs/api`、后续 `contracts` 与对应章节 API 记录 |
| 数据表、字段、索引或数据所有权 | Migration、数据设计说明、ADR（重大取舍） |
| 配置项、环境变量或默认值 | 配置参考、部署文档、`.env.example` |
| 故障恢复或值班操作 | 后续 `docs/runbooks`、QA 故障演练记录 |
| 章节设计推导或风险假设 | `docs/design-thinking/lessons`、必要时 ADR |
| 面试题型、回答边界或外部来源 | `docs/interview/lessons`；技术事实仍回链官方资料和项目证据 |
| 章节完成状态 | `docs/course/status.csv`、章节正文、`docs/qa/lessons`、设计手记与面试问答 |

## 漂移检查

自动检查由 `make doc-check` 执行，覆盖结构性漂移。语义漂移由 PR 模板和评审处理：

- 当前行为是否与 README 和架构图一致？
- 新选择是否已有 ADR，旧 ADR 是否需要标记 superseded？
- Schema 和接口示例是否来自当前实现而不是记忆？
- QA 记录是否写明命令、日期、结果与剩余风险？
- 设计手记能否从事实重放需求与取舍，并明确失败模型、假设和重评条件？
- 面试问答是否区分项目事实、官方事实、面经启发和社区讨论，且没有夸大当前实现？
- 规划能力是否被误写为已经上线？
- 本节是否在 `docs/api/lessons/lesson-XX.md` 登记了前端 API 变化，或明确写明没有真实 API 变化？

文档检查失败与测试失败同等阻止合并。
