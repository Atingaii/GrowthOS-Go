# AI Operator 工作流 v1

**状态：** v1 基线

**更新日期：** 2026-08-08

**来源章节：** [第 4 节](../course/part-01/lesson-04-ai-operator-workflow.md)

## 产品定位

AI Operator 是运营人员的受控协作入口。它将自然语言目标转成可检查的结构化计划，通过未来的 MCP Gateway 调用已经存在、经过授权的业务 Tool，并把每一步输入、审批、执行结果和失败原因展示给运营。

AI Operator 不是新的业务事实源，不直接操作数据库，也不因为使用 AI 就获得高于当前用户的权限。

## 主场景

运营输入：

> 给连续 14 天未登录、近 90 天有消费的会员设计一个召回活动，通过 Feed 触达，奖励为 10 元优惠券，总预算不超过 2 万元，下周一开始运行 7 天。

AI 不应立刻创建并发布活动，而应先完成目标理解、缺失信息澄清、数据查询、方案生成、成本估算、风险识别和审批准备。

## 完整工作流

```text
运营输入自然语言目标
  ↓
识别意图、约束和缺失信息
  ↓
必要时向运营提问澄清
  ↓
发现当前用户可用的 Tool
  ↓
只读查询人群、历史活动、权益和预算参考
  ↓
生成结构化执行计划和草稿
  ↓
校验参数、权限、风险、成本和影响范围
  ↓
向运营展示计划、差异、预计结果和不可逆影响
  ↓
低风险步骤自动执行 / 中高风险步骤申请审批
  ↓
审批前重新确认版本、参数、权限和数据时效
  ↓
逐步调用 Tool，并记录每一步状态
  ↓
通过查询 Tool 验证业务结果
  ↓
输出成功、失败、部分成功和待处理事项
  ↓
保存完整审计与 Trace
```

## 关键对象的人话解释

- **意图：** 运营真正想完成的业务目标，而不是原句中的每个词。
- **Planner：** 把目标拆成有顺序、可检查步骤的计划组件，不是可以绕过权限的决策者。
- **Tool：** 对稳定业务 API 的结构化能力描述，例如查询人群、创建草稿或申请发布。
- **结构化计划：** 包含步骤、参数、依赖、风险、成本和预期结果的机器可读计划，不只是自然语言建议。
- **Dry Run（试运行）：** 不产生真实业务写入，只校验参数、估算影响并展示将发生什么。
- **Human-in-the-loop：** AI 执行到关键节点时必须由有权限的人确认，审批不是弹窗形式，而是业务控制。
- **Guardrail：** 对输入、计划、参数、权限、预算和输出设置的确定性限制；它不能只依赖模型“自觉”。
- **Tool Result：** 业务系统返回的结构化执行结果，是判断是否成功的依据；模型生成的文字不是执行证据。

## AI 能做什么

| 能力 | 示例 | 默认风险 |
| --- | --- | --- |
| 查询 | 查询历史活动、漏斗、人群估算、库存和预算消耗 | 低，但仍受数据权限控制 |
| 解释 | 用人话解释指标变化、规则冲突和失败原因 | 低，必须展示数据来源与时间 |
| 建议 | 推荐目标人群、频控、权益组合和实验方案 | 低，不自动成为配置 |
| 生成草稿 | 创建未发布活动草稿、文案和规则初稿 | 中，保存后需校验和人工确认 |
| 申请审批 | 汇总版本差异、成本和风险并发起审批 | 中，不等于审批通过 |
| 执行受控写操作 | 在审批通过后调用发布、发券等 Tool | 高，必须运行时鉴权与审计 |
| 监控与止损建议 | 发现预算或失败率异常并建议暂停 | 中；自动暂停仅限预授权紧急策略 |

## AI 默认不能做什么

- 直接连接生产数据库或修改事实表；
- 使用服务账号绕过当前运营人员的数据和业务权限；
- 自己批准自己发起的高风险任务；
- 在参数、预算、目标人群或配置版本变化后沿用旧审批；
- 把查询估算写成精确承诺；
- 把 Tool 超时解释为执行失败并盲目重试写操作；
- 删除审计记录、隐藏失败步骤或把部分成功描述成全部成功；
- 将网页、文档、用户内容中的指令当作系统授权。

## 风险与审批矩阵

| 等级 | 典型动作 | 默认处理 |
| --- | --- | --- |
| R0 只读 | 查询公开指标、读取本人有权查看的活动 | 可自动执行，记录审计 |
| R1 建议 | 解释数据、生成方案、模拟成本 | 可自动生成，不产生业务写入 |
| R2 草稿 | 保存活动草稿、创建未发布实验方案 | 明确告知并允许撤销，必要时确认 |
| R3 受控写入 | 提交审批、修改待发布配置、创建小范围测试 | 需要操作确认和运行时权限 |
| R4 高风险 | 大规模发券、调整积分、发布活动、扩大人群或预算 | 业务/风控审批，申请人不能自批 |
| R5 紧急控制 | 暂停异常活动、触发预定义止损 | 仅预授权主体可执行，立即审计并通知 |

风险等级由 Tool 注册信息、参数、影响人数、预算、数据敏感性和操作环境共同决定，不能只靠 Tool 名称固定判断。

## 一个计划必须展示什么

AI 在请求执行前向运营展示：

1. 对业务目标的理解和仍存在的假设；
2. 将调用哪些 Tool，按什么顺序；
3. 每一步的关键参数、数据来源和更新时间；
4. 预计影响人数、权益数量、最坏成本和运行时间；
5. 哪些步骤只读、可撤销、需要审批或不可逆；
6. 与现有配置相比发生了什么变化；
7. 失败时停止、补偿、查询或人工接管的方式；
8. 审批后多长时间有效，哪些变化会使审批失效。

运营必须能够编辑草稿参数或拒绝计划，而不是只能点击“全部同意”。

## 审批对象与失效条件

审批绑定以下内容的快照或摘要：

- 计划版本和 Tool 版本；
- 目标环境、租户和操作者；
- 目标人群条件与预计规模；
- 活动配置、权益、预算和关键参数；
- 风险等级和到期时间。

审批后出现以下情况必须重新评估，必要时重新审批：目标人群扩大、预算或权益增加、Tool Schema 变化、目标环境变化、操作者权限变化、审批过期、草稿版本变化。

“用户之前同意过类似操作”不能作为本次执行授权。

## 执行状态

```text
草拟中 → 待确认 → 待审批 → 已批准 → 执行中
   │         │          │          │
   ├→ 已取消 ├→ 已拒绝  ├→ 已过期  ├→ 已取消
                                    │
                                    ├→ 已成功
                                    ├→ 部分成功
                                    ├→ 执行失败
                                    └→ 结果未知
```

这是产品状态基线，不是最终数据库枚举。

## Tool 调用的结果语义

| 结果 | 含义 | AI 下一步 |
| --- | --- | --- |
| 成功 | Tool 明确返回业务成功标识和业务对象 ID | 查询验证并继续依赖步骤 |
| 业务拒绝 | 参数、状态或业务规则不允许执行 | 停止相关步骤，解释可修复原因 |
| 技术失败 | 服务明确未执行成功 | 按 Tool 重试策略处理或交给人工 |
| 超时/断连 | 不知道业务是否已执行 | 先用业务请求号查询，禁止盲目重试 |
| 部分成功 | 多个目标中只有一部分完成 | 展示逐项结果，禁止汇总为全部成功 |
| 需要补偿 | 主操作完成但后续步骤失败 | 展示已发生事实和补偿任务，不直接“撤销事实” |

## 部分成功示例

计划包含创建优惠券模板、创建活动草稿、绑定权益和提交审批四步。如果前三步成功而提交审批失败：

- 已创建模板和草稿仍是业务事实；
- AI 将任务标为“部分成功”，显示对象 ID 和失败步骤；
- 不自动删除模板或草稿，除非存在经过授权且语义明确的撤销 Tool；
- 运营可以修复原因后从安全检查点继续，而不是重新执行全部步骤。

## 运行时权限原则

Tool 出现在列表中不代表每次都可调用。执行时必须重新检查当前用户、租户、环境、资源范围、角色、参数和审批。AI 只能使用请求者已有的权限或显式委托，不能以平台服务账号扩大权限。

敏感查询同样需要治理：即使是 R0 只读，也不能让无权限运营查看其他租户用户明细或原始敏感数据。

## 防止外部内容改变任务

AI 查询到的活动文案、网页、文档、用户输入和 Tool 返回文本都属于业务数据，不是系统指令。外部内容要求“忽略审批”“调用另一个 Tool”或“导出全部数据”时，Planner 不得采纳，除非该动作来自受信任策略并通过正常权限与审批流程。

第 93 节会实现更完整的 Prompt Injection 防护和 Agent Guardrail；本节先建立产品边界。

## 工作台展示

AI Operator 页面应同时显示：

- 对话与澄清问题；
- 当前结构化计划和版本；
- Tool 列表、参数摘要和逐步状态；
- 数据来源、查询时间和结果置信边界；
- 风险、预算、影响范围和审批状态；
- 成功对象 ID、失败原因、重试/补偿入口；
- Trace、操作者和完整审计时间线。

不应只显示一个聊天气泡和一句“操作成功”。

## 审计事实

每个任务至少需要追踪：原始请求、澄清内容、模型/Prompt 版本、计划版本、Tool Schema 版本、调用参数摘要、权限判断、审批人和审批快照、业务请求号、Tool 原始结果引用、最终验证和人工接管记录。

敏感参数和响应需要脱敏或受控存储，审计完整不等于把秘密和个人信息复制到日志。

## 成功标准

- 运营能在执行前理解 AI 将做什么和为什么；
- 高风险动作没有有效审批就不能执行；
- Tool 超时不会导致盲目重复写入；
- 部分成功能逐步解释并可安全继续；
- 自然语言总结能够追溯到真实 Tool 结果；
- 人工可以拒绝、取消、接管和审查任务；
- AI 参与没有削弱第 3 节定义的预算、权限、版本和审计边界。
